# Player - 사장님 캐릭터 공통 몸체

> 경로: `Source/HuoguoHuoguo/Player/` (경영/탐험 캐릭터와 컨트롤러도 이 폴더) · 마지막 갱신: 2026-11-28

## 역할

경영 파트와 탐험 파트의 사장님이 함께 쓰는 몸체. 카메라와 중력처럼 파트마다 다른 것은 `Shop/`, `Explore/`의 하위 클래스가 정한다.

## 파일

### HGBossCharacter (.h/.cpp)
추상 클래스 (`AHGShopBossCharacter`, `AHGExplorerCharacter`가 상속).
- 캡슐 반지름 40, 반높이 92. 몸은 이동 방향으로 돈다(`bOrientRotationToMovement`), 컨트롤러 회전은 몸에 쓰지 않는다.
- 이동: MaxWalkSpeed 520, JumpZVelocity 620, AirControl 0.45, RotationRate (720, 720, 720).
  Pitch/Roll 회전 속도는 행성에서 몸을 새 "위"에 맞춰 세우기 위해 필요하다 (평면에서는 영향 없음).
- 외형: 엔진 기본 도형 자리 표시 (원기둥 몸통 흰색, 구 머리, 헬멧 구 청록). `SetSuitVisible`로 헬멧 표시.
  - 외형 축: 캡슐 가운데 VisualPivot(몸 전체 회전, 예: 3단 점프 공중제비) 아래 발 위치 VisualRoot(크기 = 눌림/늘어남, 발이 땅에 붙은 채로). 부품과 복셀은 모두 VisualRoot 아래에 FeetOffset(92)만큼 올려 붙인다.
  - 외형 준비는 `BeginPlay`가 아니라 `PostInitializeComponents`(스폰 직후, 게임 월드만)에서 한다 (2026-11-28). 엔진 표준 스폰에서는 컨트롤러의 BeginPlay가 캐릭터보다 먼저 와서, 컨트롤러가 켠 중력과 차림이 캐릭터의 BeginPlay에 덮이지 않게 하려는 것이다. 탐험 캐릭터의 카메라 거리, 걷기 가속, 착지 먼지 준비도 같다.
  - 처음 차림 = `bWearSpaceSuit`(디테일 "우주복 차림", 탐험 캐릭터 기본 켬, 가게 사장님 기본 끔). 예전에는 시작점이 정했다.
  - 복셀 그림체(`hg.Voxel`, 기본)면 주인공 모습을 복셀로 만들고 자리 표시 도형을 숨긴다 (`BuildVoxelBody`). 주인공 = 식당 경험 없는 배불뚝이 직장인 (기획서 "이야기"): 흰 와이셔츠, 볼록한 배, 반쯤 풀린 빨간 넥타이, 회색 정장 바지, 검은 구두, 허리띠, 짧은 검은 머리, 네모 안경.
  - 앞치마(빨강, 배 앞 허리 아래)와 헬멧은 따로 복셀화한다 (같은 묶음이면 겹치는 칸을 덮어써서 숨겼을 때 구멍이 난다). `SetSuitVisible(true)` = 헬멧 보임 + 앞치마 숨김(우주), `false` = 앞치마(가게).
  - 확인됨: 가게에서 흰 셔츠/검은 머리/회색 바지/앞치마 차림, 행성에서 헬멧.
  - 이 복셀 모습은 자리 표시다. 주인공 설정이 은퇴한 복면 레슬러로 바뀌어서(기획서 "이야기") 지금 복셀(직장인)은 옛 설정이다.
    정식 모델은 2D 레퍼런스 그림(생김새와 조건은 `Docs/Art/Protagonist.md`)을 Tripo로 3D로 뽑아 자동 리깅해서 넣는다.
- `Move(Input)`: 카메라(컨트롤러) 회전을 `GetMoveFrame()` 좌표계로 옮겨 Yaw만 남기고 앞/오른쪽을 구한다.
  카메라를 어느 방향으로 돌려도 W = 화면 위쪽(카메라가 보는 쪽).
- `GetMoveFrame()`: 기본 항등 회전. 구형 중력을 쓰는 하위 클래스가 바꾼다.
- 시험용 방향 화살표 (2026-11-28): 콘솔 `hg.ShowFacing 1`. 사장님 허리에서 빨강 = 캐릭터(캡슐) 앞, 초록 = 모델(메시) 앞(메시 Y축), 파랑 = 실제 이동 방향, 노랑 = 입력(가속) 방향, 흰색 = 위.
  걸을 때 빨강, 초록, 파랑이 같은 방향이어야 정상이다. 꺼져 있으면 `Tick`에서 정수 비교 하나로 끝난다 (`ENABLE_DRAW_DEBUG` 빌드만).
  엔진 스크린샷(HighResShot)에는 디버그 선이 찍히지 않아서 화면으로 확인하지 못했다. PIE나 게임 창에서 직접 본다.

### HGBossAnimInstance (.h/.cpp) (2026-11-28)
사장님 애님 BP(`ABP_HG_Boss_*`)의 부모 C++ 클래스 (Under One Umbrella의 `UUOUPlayerAnimInstance`와 같은 방식).
- 매 프레임 캐릭터의 위(`GetMoveFrame()`의 위, 행성에서는 중력 반대) 기준으로 속도를 나눠 변수로 내준다:
  `Speed`(발밑 평면 속도), `VerticalSpeed`(위 방향 속도), `IsMoving`(속도 3 이상 + 가속 입력), `IsInAir`(낙하/점프), `IsFloating`(무중력 비행), `GravityUp`, `OwnerBoss`.
- 템플릿 그래프는 월드 Z를 위로 보고 수평 속도를 구해서 행성 옆면에서 걷기/뛰기 판단이 틀릴 수 있다. 이 값들은 어디서나 맞다.
  다만 지금 그래프는 아직 템플릿 변수(`GroundSpeed`, `ShouldMove`, `IsFalling`)를 읽는다. 그래프의 노드를 이 변수로 바꾸면 된다 (이름이 겹치지 않게 지었다).

- 정식 모델 (2026-11-27): 기본 `Mesh` 컴포넌트 자리. 어떤 모델을 쓸지와 크기는 C++이 아니라 블루프린트가 정한다.
  - C++이 정하는 것: `Mesh`는 VisualRoot(발) 아래에 붙고 Yaw -90 (모델 앞 +Y 규칙, 언리얼 마네킹과 같음). 처음엔 숨김.
  - 블루프린트가 정하는 것 (`BP_HG_Explorer`, `BP_HG_ShopBoss`의 Mesh 컴포넌트): 메시 `SK_HG_Boss`, 크기 1.8 (모델 키 1m → 캡슐 키 약 1.84m).
  - 스폰 직후(`PostInitializeComponents`): `Mesh`에 모델이 들어 있고 `hg.BossModel`이 1(기본)이면 모델을 보이고 자리 표시/복셀 몸은 만들지 않는다. 0이면 예전 복셀 직장인 (비교용).
  - 정식 모델이면 `SetSuitVisible`은 아무것도 바꾸지 않는다 (우주복 차림 하나뿐).
  - 확인됨: 행성에서 모델이 캡슐 키에 맞게 서고 텍스처 색(크림 우주복, 주황 띠, 보라 바이저)이 보이고, 서기/달리기/점프 동작이 나온다.

## 흐름 / 규칙

- 두 파트에 공통인 외형/이동 규칙만 여기에 둔다.
- 스켈레탈 메시가 생기면 기본 `Mesh`에 넣고 자리 표시 컴포넌트를 숨긴다.
